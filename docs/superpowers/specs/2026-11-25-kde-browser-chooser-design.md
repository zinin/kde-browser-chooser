# kde-browser-chooser — дизайн

Дата: 25.11.2026. Статус: черновик на утверждение. Размер: проект.

Пометки: **[П]** — решил пользователь, **[И]** — предложил исполнитель, возражений не было
или ещё не видел. При утверждении можно править любое **[И]**.

## Зачем

У автора вместо браузера по умолчанию стоит скрипт `browser-chooser`: на клик по ссылке показывает окно с большими плитками
(скопировать, четыре браузера, отмена), один клик — действие. Браузеры вписаны в код,
тексты только русские, тесты лежат во временной папке.

Пользователь хочет, чтобы это стало отдельным проектом: «пусть будет, плюс смогу переносить
на другие свои машины». На них стоит то же самое (Kubuntu 26.04, Plasma 6, Wayland), но
ставиться должно на любой Linux с KDE одной командой. **[П]**

**Успех:** на новой машине одна команда, и по клику на ссылку появляется окно с теми
браузерами, что там стоят, без правки кода. На нынешней машине ничего не потеряно.

## Цели

1. Репозиторий `github.com/zinin/kde-browser-chooser`: имя согласовано **[П]**; публичный,
   MIT, ветка `master`, README на английском и `README.ru.md` **[И]**.
2. Автопоиск браузеров и/или настройка **[П]**: автопоиск по умолчанию, необязательный файл
   настроек поверх **[И]**.
3. Тексты на английском (по умолчанию) и русском **[П]**, новый язык — один новый файл **[И]**.
4. Установка `curl … | sh` на любой Linux с KDE **[П]**, версия Plasma — 6 **[И]**.
5. Поведение нынешнего окна сохраняется полностью, включая «браузер выходит вперёд».
6. Машина автора переведена на новую версию — отдельный документ, не для репозитория **[И]**.

## Не делаем

- GNOME и другие рабочие столы **[П]**. Plasma 5 — сейчас нет, добавим, если понадобится **[И]**.
- Окно настроек, правила «этот сайт — в этот браузер», поиск профилей браузеров, цифровые
  клавиши, собственный значок, Flatpak, .deb/.rpm/AUR, автообновление **[И]**. Профиль браузера
  можно добавить своей плиткой.

## Чего быть не должно (провал, даже если «работает»)

- Ссылка молча потеряна или открыта не там из-за случайного клика.
- На Plasma 6 Wayland уже запущенный браузер остаётся позади других окон.
- Ошибка в файле настроек мешает открыть ссылку.
- После установки нельзя вернуть прежний браузер по умолчанию.
- В публичный репозиторий, включая историю коммитов, попали личные данные автора: пути его
  домашней папки, имя машины, сторонние программы и профили. (Авторство коммитов — как в других его
  публичных репозиториях.)

## Ограничения

- Python ≥ 3.11 (`tomllib`), системный `/usr/bin/python3`, запуск с `-I`.
- PyQt6 из пакета дистрибутива, ≥ 6.7. Из pip не годится: там свой Qt без стиля Breeze.
- Кроме PyQt6 обязательных зависимостей нет. Всё остальное (kdialog, notify-send, wl-copy,
  Klipper, libKF6WindowSystem) используется, если есть, и безопасно отсутствует.
- На Kubuntu 26.04 PyQt6 уже стоит (от него зависит `kubuntu-desktop`), поэтому там установка
  идёт без `sudo`.
- X11: окно работает, токена активации нет (как сейчас). Вне KDE поведение не обещаем.

## Подходы

| Подход | Итог |
|---|---|
| **Python + PyQt6, установщик `curl \| sh`** | **Выбран [П].** Готовый код и 52 теста; родной вид; на машинах пользователя без `sudo` |
| C++ / Qt 6 / KF6, готовый бинарник | Чище внутри, но код и тесты заново, сборки под amd64/arm64, привязка к версии Qt |
| Rust + Qt (cxx-qt, Qt Bridge) | То же, что C++, и обе привязки ещё молодые |
| Rust или Go со своим интерфейсом | Один файл для любой системы, но вид неродной |
| Пакеты .deb/.rpm/AUR | Несколько форматов и репозиториев; можно добавить позже |

## Что переносится без изменений

Исходник — прежний скрипт, его тесты, стенд вложенного KWin и мутационная проверка (где они лежат —
в документе о переводе машины). Поведение, которое обязано сохраниться:

- Плитки 180×160, значок 96 px, подпись снизу, кликается вся плитка, один клик — действие.
- Сверху адрес одной строкой, лишнее обрезано многоточием, `< > &` показаны буквально.
- Плитка прошлого выбора залита смесью 70/30 цветов Button и Highlight, фокус на ней; Enter и
  Return открывают, стрелки ходят по сетке; «Отмена», Esc и крестик закрывают.
- Первые 0,3 с от первой отрисовки клики и Enter не действуют, Esc действует.
- По выбору браузера: новый токен активации у KWin через `KWaylandExtras` (ctypes только для
  `self()`, остальное — вызовы через метаобъект Qt), ждать не дольше 0,3 с, затем закрыть окно и
  заменить процесс браузером (`execve` с `os.environ`, сброс SIGPIPE/SIGXFSZ, чужие дескрипторы
  закрыты). Почему так: клик в окне обесценивает исходный токен; проверено во вложенном KWin
  (без нового токена браузер позади, с ним — впереди).
- Не показалось окно → список kdialog с теми же пунктами; не сработал и он → уведомление
  с адресом (в прежний браузер сами не открываем: он может быть не тем). Исключение в слоте Qt,
  закрытый stderr или сбой KDE-библиотеки ссылку не теряют.
- Список kdialog не выводит уже запущенный браузер вперёд (проверено): это запасной путь, а не
  режим работы.
- Браузер не запустился, ссылка не скопировалась → уведомление, а не тишина.

Заодно закрываем отложенные мелочи прошлого ревью: в kdialog курсор на прошлом выборе
(`--default` принимает название пункта); Ctrl+C в терминале закрывает окно; нет файла
значка → значок по умолчанию; комментарий и тест сигнатур для вызова `KWaylandExtras`; недостающие
тесты (`-I`, граница дескрипторов, точное 0,3 с, код возврата kdialog, `setDesktopFileName`,
исчезновение окна до запуска).

## Новое поведение

### Плитки

1. Порядок: «Скопировать ссылку», браузеры, свои плитки, «Отмена» (всегда последняя).
2. Браузеры — записи `.desktop`, у которых: `Type=Application`; в `MimeType` есть
   `x-scheme-handler/https`; нет `NoDisplay`, `Hidden`, `Terminal=true`; `TryExec` (если указан)
   находится; `OnlyShowIn`/`NotShowIn` допускают KDE; в `Exec` есть код `%u`, `%U`, `%f` или `%F`.
   Себя и старый `browser-chooser.desktop` исключаем. `mimeapps.list` не учитываем. Konqueror так не
   найдётся (у видимой записи нет `MimeType`) — добавляется своей плиткой.
3. Где ищем, по порядку: `$XDG_DATA_HOME/applications`, затем каждый `$XDG_DATA_DIRS/applications`,
   затем, если их там нет, `~/.local/share/flatpak/exports/share`, `/var/lib/flatpak/exports/share`,
   `/var/lib/snapd/desktop` (с `/applications`). ID — путь от `applications` с `/`→`-`, без
   `.desktop`; первая найденная запись с этим ID перекрывает остальные (в том числе `Hidden=true`).
   Две видимые записи с одинаковой командой `Exec` — одна плитка.
4. Без настроек браузеры идут по названию. Название — `Name[язык окна]`, иначе `Name`. Значок —
   `Icon` (имя темы или путь).
5. Сетка: до 4 плиток — 2 столбца, до 9 — 3, больше — 4. (На машине пользователя — нынешние 3×2.)
6. Поиск идёт при каждом запуске; окно появляется не позже, чем на 0,1 с медленнее нынешнего.
7. Без ссылки (запуск из меню) плитки «Скопировать» нет: раньше она очищала буфер. Несколько
   ссылок: показывается первая и «(+N)», копируются все, по одной в строке, браузер получает все.

### Запуск браузера

`Exec` разбирается по спецификации Desktop Entry (экранирование, кавычки, `%%`; `%i` → `--icon` и
значок, `%c` → название, `%k` → путь файла; прочие устаревшие коды отбрасываются). `%U`/`%F` получают
все ссылки сразу, `%u`/`%f` — по одной: по запуску на каждую, последний заменяет наш процесс (так велит
спецификация; иначе, например, Angelfish теряет все, кроме первой). Аргументы flatpak `@@u … @@`
передаются как есть.

### Настройки

`$XDG_CONFIG_HOME/kde-browser-chooser/config.toml`, необязательный; в репозитории —
`config.example.toml`:

```toml
language = "ru"                          # без строки — язык системы
order  = ["copy", "google-chrome", "firefox_firefox"]   # остальные — следом, по названию
hide   = ["opera"]                       # можно и "copy"
rename = { "yandex-browser" = "Яндекс Браузер" }

[[tile]]                                 # своя плитка
id = "chrome-work"                       # необязательно; по умолчанию — из названия
name = "Chrome: работа"
icon = "google-chrome"                   # имя темы или путь; необязательно
command = "google-chrome-stable --profile-directory='Profile 1'"
```

- ID плитки браузера — как в `--list`. Неизвестные ID в `order`, `hide`, `rename` молча
  пропускаются (браузер мог быть удалён).
- `command` делится по правилам оболочки; ссылки встают на место `%u`/`%U` или в конец.
- Ошибка в файле (синтаксис, неизвестный ключ, не тот тип): окно показывается так, будто файла нет,
  и приходит уведомление, где ошибка.

### Язык

Язык окна: `language` из настроек, иначе первый подходящий из `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`,
`LANG`, иначе английский. Тексты — `locales/en.toml` и `locales/ru.toml`; язык, где нет какой-то
строки, берёт её из английского. `.desktop` содержит `Name` и `Comment` на обоих языках.
Установщик и `--help` — только английские **[И]**.

### Копирование и уведомления

Копирование: на Wayland `wl-copy`, если есть, иначе Klipper по D-Bus (`org.kde.klipper`, `/klipper`,
`setClipboardContents`); на X11 — Klipper. Klipper — часть Plasma, поэтому ставить ничего не нужно, но
он пишет и в буфер выделения (вставка средней кнопкой), а `wl-copy` — нет, поэтому `wl-copy` первый.
Не вышло ничего → уведомление об ошибке.

Уведомления: `notify-send`, нет его → прямой вызов `org.freedesktop.Notifications` по D-Bus любым
доступным средством (без PyQt6 — `busctl`, `gdbus` или `dbus-send`). `kdialog --passivepopup` не
используем: без сервера уведомлений он не завершается.

### Командная строка

`kde-browser-chooser [--] [URL…]`; `--list` (ID, название, команда, значок — для настроек), `--version`,
`--help`. Параметры действуют, только если параметр — единственный аргумент: обработчик ссылок не
должен падать на необычных аргументах. В `.desktop`: `Exec=<путь> -- %U`.

### Файлы программы

- Один исполняемый файл — zipapp с shebang `/usr/bin/python3 -I` (проверено: импорт из архива с `-I`
  работает). Внутри пакет `kde_browser_chooser` и `locales/`. Всё своё загружается до показа окна:
  обновление под открытым окном ломает поздний импорт из архива (проверено).
- Прошлый выбор — `$XDG_STATE_HOME/kde-browser-chooser/last` (ID плитки).
- `app_id` и запись — `kde-browser-chooser(.desktop)`; значок `internet-web-browser`.

## Установщик

```sh
curl -fsSL https://raw.githubusercontent.com/zinin/kde-browser-chooser/master/install.sh | sh
curl -fsSL …/install.sh | sh -s -- --uninstall
```

По образцу `graft/install.sh`: POSIX sh, весь код в `main`, релиз с GitHub, сверка с `SHA256SUMS`.

1. Не Linux или запуск от root → отказ. Не KDE → предупреждение и вопрос.
2. Нет `/usr/bin/python3` ≥ 3.11 → отказ. Нет PyQt6 → показать команду пакетного менеджера (apt,
   dnf, pacman, zypper; на системах с ostree — `rpm-ostree`, без попытки самому), спросить, выполнить
   через `sudo`. Неизвестный менеджер — просто написать, что нужно. NixOS не поддерживаем.
   **Без PyQt6** файл ставим, но браузером по умолчанию не предлагаем, если нет и kdialog (на Arch
   `plasma-meta` его не ставит): показать окно было бы нечем. С kdialog — предлагаем, ответ по
   умолчанию «нет», с пояснением, что будет список и браузер может остаться позади.
3. Положить файл в `~/.local/bin` (заменить атомарно), запись — в `~/.local/share/applications`,
   обновить базы (`update-desktop-database`, `kbuildsycoca6`, если есть).
4. Спросить «сделать браузером по умолчанию?» (Enter — да; без PyQt6 — см. п. 2). Назначаем через
   `xdg-settings`: на KDE он меняет http, https, text/html и `BrowserApplication` в kdeglobals; к ним
   application/xhtml+xml. Прежнее значение запоминаем **отдельно для каждого** из пяти, в
   `$XDG_STATE_HOME/kde-browser-chooser/previous-defaults`, и только если это не мы. Проверить, что
   назначение сработало.
5. Вопросы читаются с `/dev/tty`. Без терминала пакеты не ставить и браузер по умолчанию не менять,
   если нет `--yes`.
6. Повторный запуск — обновление: ничего не спрашивает о том, что уже сделано.
7. `--uninstall`: вернуть каждое из пяти прежних значений, если сейчас там всё ещё мы (программа
   исчезла — сказать, что назначить вручную), удалить свои файлы и состояние; настройки оставить,
   с `--purge` удалить и их.
8. Переменные `KBC_VERSION`, `KBC_INSTALL_DIR`, `KBC_BASE_URL` (для тестов).

## Репозиторий

Локально `~/git/kde-browser-chooser`. Код в `src/kde_browser_chooser/` (поиск, настройки, язык, окно,
токен, запуск, запасной путь — отдельными модулями), `install.sh`, `tests/`, `tests/kwin/` (стенд),
`tools/` (сборка zipapp, мутации), `README.md`, `README.ru.md`, `config.example.toml`, `CHANGELOG.md`,
`LICENSE`, `CLAUDE.md` (как запускать тесты и стенд, грабли). Два снимка окна (английский, русский) из
вложенного KWin.

**CI:** pytest (offscreen), `shellcheck`, сборка; установщик в контейнерах Ubuntu 26.04, Debian 13,
Fedora, Arch, openSUSE Tumbleweed: поставить с локально собранного файла, увидеть PyQt6, запустить
окно offscreen, удалить. Имена пакетов PyQt6 подтверждаются там же.
**Релиз:** тег `v*` собирает файл и `SHA256SUMS`, как в graft. Первая версия — `v0.1.0`.

**Стенд KWin** (только локально): настоящие клики через EIS, проверка, что браузер выходит вперёд. Две
граблины, которые нельзя повторить: без `bus.conf` без `servicedirs` и `prlimit --core=1:1` во
вложенном сеансе падают портал и ksecretd, и хост копит дампы; снятый `WAYLAND_DISPLAY` не
изолирует — libwayland возьмёт `wayland-0` из `XDG_RUNTIME_DIR`, поэтому подменяется и он.

**Порядок:** пустой `master` (README-заготовка, LICENSE) → ветка с кодом и документами → PR
(ревью Codex) → слияние пользователем → тег → релиз. Документы из `docs/superpowers/` удаляются
отдельным коммитом перед PR, но остаются в публичной истории ветки, поэтому в неё идёт только эта,
вычищенная версия. Перед каждым push — проверка всей истории (`git log -p`) на личные данные.
